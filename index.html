Podcasting is distributed, so linking to a show or episode is different on every platform. This guide documents the link formats you can observe for each one: which links you can build from open podcast identifiers, which need the platform's own ID or an API lookup, and which URL schemes open each app.

Tags describe what a platform is. They overlap, and they aren't recommendations. Placeholders like ${appleID} are defined in the glossary.

How links are built

Direct link
Built only from open identifiers: the Apple Podcasts ID, the feed URL, the podcast GUID, Podcast Index IDs, the episode GUID or the media URL.
API lookup
Needs the platform's own ID, which its public API can find.
ID required
Needs the platform's own ID, with no known public way to look it up.
Search
Lands on a search, which may not find an exact match.
Feed link
An app URL scheme that takes a feed URL.
Deep link
An app URL scheme that takes a link to the platform's own content.
Opens app only
An app URL scheme that opens the app but isn't known to open specific content.

Where both exist, an https link is usually better than a URL scheme: if the app is installed, a universal link opens it, and if not, the link still works in a browser.

Add or fix a platform

Every row on this page comes from one file, _data/platforms.json. Edit that platform's record (the schema describes each field), run node scripts/validate.mjs, and open a pull request with an example URL showing the link works. Other tools can fetch the same data from platforms.json.
